# Attribution and limitations

The 6.4140625 MiB terminal change is 5.6875 MiB journal plus 0.7265625 MiB nginx, not a single-directory change. Full-sample endpoint growth is separately reported. All measured log directories are nondecreasing; nginx and total `/var/log` increase in every interval. The journal increases in five allocation steps. Sequential `du` calls leave a 4096-byte residual in 736 samples and zero in one: no unexplained growing residual is concealed.

The endpoint inventories embed complete nginx access/error content. The final access file retains the entire initial prefix, adding 52,231 lines / 9,296,534 serialized bytes. Browser user agents account for 43,461 requests; Python clients 8,769; curl one. GET `/api/msd` alone contributes 43,664 requests. The continuous video requests contribute only two completed access entries; disabling access logging primarily removes repeated API polling here. Error content adds 2,941 bytes associated with the scheduled restart. Inventory times extend beyond resource endpoints, so these apparent-byte totals are not forced to equal sampled allocated-block deltas.

The live journal contains 53,307 kvmd messages (14,447,110 rendered bytes), of which 51,998 are `aiohttp.access`. Browser/API polling is therefore the dominant measured message source in both nginx and kvmd. kvmd behavior and its access auditing will remain unchanged; its messages will fall under the shared journal quota.

Fresh SSH/sudo commands are diagnostic traffic, not a presumed appliance idle workload. There are 5,775 sshd-session messages, 3,465 sudo messages, 2,310 unix_chkpwd messages and 5,890 runuser messages during the sampled interval. The first three total 1,273,624 rendered bytes; runuser adds 628,942. Sampler-adjacent windows contain 3,714 sshd, 2,230 sudo and 1,488 unix_chkpwd messages (819,582 rendered bytes). This is a significant secondary contribution, about 65 percent of the first three identifiers' bytes, but much smaller than kvmd's 14.4 MB rendered stream. Temporal windows may include nearby cycle activity and are not exclusive per-session attribution. A controlled no-sampler counterfactual was not archived, so exact causal on-disk bytes cannot be assigned.

The median resource interval is 60.108 seconds. Hourly sample/cycle/journal counts are in correlation.json. There are 139 HID/MSD cycles and the API category counts repeat in exact per-cycle multiples (for example 139 unauthorized keyboard events and 278 MSD connection changes). That explains a periodic secondary traffic component. runuser session messages arise during helper activity. Browser polling supplies the near-continuous background load. Five coarse journal allocation steps cannot establish a linear message-to-allocated-byte relation because of compression, indexing and preallocation.

Neither journal allocation decreases nor rotation/drop messages were observed. Complete nginx endpoint content demonstrates retained access history. The archive has no individual journal filenames/inodes/cursors or structured journal export; rotation with no net decrease cannot be excluded. No journal retention bound was demonstrated. The live text carries SYSLOG_IDENTIFIER-like prefixes but not `_SYSTEMD_UNIT`, so exact unit grouping is unavailable. No kernel or nginx identifier occurs in the live sampled window; nginx regular-file logs are accounted separately. Rendered message bytes are approximate serialization sizes, not actual journal storage usage.
